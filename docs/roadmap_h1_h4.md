# Roadmap: ตอบและวัดผลสมมติฐาน H1-H4

โครงการ: ไข้เลือดออก × สภาพอากาศรายจังหวัด (TRENDS 2016-2025), หน่วย = จังหวัด-สัปดาห์, target = D (การเติบโต 4 สัปดาห์), H = 4 สัปดาห์

**หลักคิด:** ล็อกนิยาม → วัดข้อหลัก (H4) → วัดข้อกลไก (H1-H3) → ตรวจความสอดคล้อง → รายงาน
ทำ H4 ก่อนเพราะเป็นข้อหลัก ทำได้เร็ว และผลของมันบอกว่า H1-H3 ควรลงลึกแค่ไหน

## สมมติฐาน (จาก proposal หัวข้อ 5)

| ID | สมมติฐาน | Metric | เกณฑ์ตัดสิน | ถ้าไม่สนับสนุน |
|---|---|---|---|---|
| H1 | ฝนมีสัญญาณต่อ D ที่เหลือหลังหักฤดูกาลและประวัติ | partial Spearman (คุมประวัติ) ภายในจังหวัด, anomaly ฝน lag 0-4 | \|ρ\| ≥ 0.10 และเครื่องหมายเดียวกันใน ≥ 4 จาก 5 fold หลัก | ฝนไม่มีสัญญาณเชิงเส้นเพิ่มเติม ไม่ต้องใส่เป็นฟีเจอร์เด่น |
| H2 | อุณหภูมิมีสัญญาณต่อ D ที่เหลืออยู่ | เหมือน H1 กับ anomaly t_max, t_min | เหมือน H1 | อุณหภูมิไม่มีสัญญาณเพิ่มเติม |
| H3 | สัญญาณของอากาศ (ถ้ามี) อยู่ที่ lag ที่ใช้พยากรณ์ได้จริง | ρ ต่อ lag (lag 0-4 ขยายถึง 8) และโปรไฟล์ข้าม fold | มี lag อย่างน้อยหนึ่งค่าผ่านเกณฑ์ H1/H2 และ lag ที่ดีที่สุดไม่อยู่ที่ขอบ (ถ้าอยู่ที่ lag 4 ให้ขยายถึง 8 ก่อนสรุป) | ไม่ใส่ weather lag เป็นฟีเจอร์ในโมเดลสุดท้าย |
| H4 (หลัก) | เพิ่มอากาศให้ M0 แล้วลดความคลาดเคลื่อนของการพยากรณ์ D | M0 (ประวัติ+ฤดูกาล) vs M1 (M0 + อากาศ lag 0-4 + anomaly): ผลต่าง MAE ของ D ต่อ fold, block bootstrap ภายในปีบนจังหวัด | ลด MAE ≥ 5% และ M1 ดีกว่าใน ≥ 4 จาก 5 fold และ CI ของผลต่างไม่คร่อมศูนย์ | รายงานว่าอากาศไม่เพิ่มประโยชน์ในข้อมูลนี้ (ผลที่ยอมรับได้) |

## สถานะหลักฐานตอนนี้ (2026-11-20) — ผลจริงจาก pipeline

| ID | ผลที่ได้ | คำตัดสิน |
|---|---|---|
| **H1** | partial Spearman rain vs D: \|ρ\| สูงสุด 0.075 ที่ lag 2 (เกณฑ์ 0.10) ทุก lag ต่ำกว่าเกณฑ์; ρ_real < placebo P95 ทุก lag | **❌ ไม่ผ่าน** |
| **H2** | tmax/tmin มี \|ρ\| ≈ 0.104-0.110 ที่ lag 1-2 (เกิน 0.10) แต่เครื่องหมายไม่สม่ำเสมอข้าม 5 fold; ρ_real < placebo P95 ทุกกรณี | **❌ ไม่ผ่าน** |
| **H3** | H1/H2 ไม่ผ่านทั้งคู่ → ตัดสินไม่ได้ตามนิยาม | **— ตัดสินไม่ได้** |
| **H4** | HuberRegressor: M1 ดีกว่าใน 1/5 fold; ΔMAE range −19% ถึง +5.6%; Sensitivity (ElasticNetCV, HistGBR, XGBRegressor*, TabMMini*) สอดคล้องกัน | **❌ ไม่ผ่าน** (*กำลังรันอยู่) |

**ข้อสรุป:** อากาศไม่เพิ่มประโยชน์ในข้อมูลชุดนี้ — เป็น outcome ที่ proposal ระบุว่ายอมรับได้ ผลสอดคล้องกับทีม DS (XGBoost ΔMAE 4.24%, TabM-mini ΔMAE 2.44% ไม่ผ่านเกณฑ์เช่นกัน) สัญญาณอยู่ที่ biological lag 5-8 (ทีม DS พบ) ซึ่งอยู่นอกช่วง H1/H2 ที่ล็อกไว้ (lag 0-4)

## ขั้น 0: ล็อกนิยามก่อนดูผล (สำคัญที่สุด)

บันทึกเป็นไฟล์ config เดียว ผูกกับ hash ของ run ถ้าข้ามขั้นนี้ ผลที่ได้จะแก้ตามใจได้เสมอ

| เรื่อง | ต้องตัดสินใจ | เหตุผล |
|---|---|---|
| M0 มีอะไร | ตามที่ proposal เขียน (ประวัติ + ฤดูกาล) ฝั่ง DS ใส่จังหวัดข้างเคียงด้วย จะใส่ใน M0 หรือแยกเป็นการทดลองต่างหาก | ถ้า M0 ต่างจาก proposal ผล H4 ไม่ตรงกับคำถามที่ตั้งไว้ |
| M1 มีอะไร | M0 + อากาศ lag 0-4 + anomaly (ตามนิยาม) | นิยามเดียวตลอด รูปแบบอื่นเป็น sensitivity |
| โมเดลหลักของ H4 | เลือกโมเดลเดียวล่วงหน้า (Huber หรือ EN) | ลองหลายโมเดลแล้วเลือกที่ผ่านจะได้ผลดีเกินจริง โมเดลอื่นเป็นการเช็กความทนทาน |
| วิธีรวมผล H1/H2 | partial ρ รายจังหวัดแล้วรวมอย่างไร (เช่น มัธยฐานข้ามจังหวัดต่อ fold); "เครื่องหมายเดียวกัน ≥ 4/5 fold" นับที่ระดับ fold | proposal ยังไม่ระบุ และจังหวัดไม่อิสระต่อกัน (anomaly โรคสัมพันธ์ ≈ 0.6) |
| การทดสอบหลาย lag | 3 ตัวแปร × 5 lag = 15 การทดสอบ นิยามว่า "ผ่าน" อย่างไร | ป้องกันผ่านด้วยความบังเอิญ |
| การเลือกฟีเจอร์ | ห้ามใช้ปีทดสอบเลือกฟีเจอร์ ใช้ inner split ใน train | ปัญหาเดียวกับผล Huber 4.22% |
| กติกาคงที่ | `week_days == 7`; ฟีเจอร์สร้างจากแถวต้นทาง t; anomaly คำนวณจาก train ของแต่ละ fold; 5 fold หลัก (test = 2019, 2022, 2023, 2024, 2025, expanding train, gap 4 สัปดาห์); 2020/2021 เป็น fold เสริมแยก; seed = 342 | ตาม proposal และ EDA |

- [x] ตกลง M0/M1 และบันทึกลง config (`config/analysis.toml`)
- [x] เลือกโมเดลหลักของ H4 (HuberRegressor ε=1.35, α=1.0)
- [x] กำหนดวิธีรวมผล H1/H2 และเกณฑ์ "ผ่าน" (median ρ per fold, same-sign ≥ 4/5)
- [x] เขียนเอกสารนิยามหน้าเดียว (`docs/pre_analysis_spec.md`)

## ขั้น 1: ตารางฟีเจอร์ที่รองรับทุกสมมติฐาน

- ดึงตารางฐานจาก DuckDB สร้าง D, ประวัติ, ฤดูกาล
- อากาศ lag 0-8 จากแถวต้นทาง t (lag 0-4 มีในตารางแล้ว lag 5-8 สร้างเพิ่มจากข้อมูลรายวัน) H3 ต้องใช้โดยตรง
- anomaly ต่อ fold (ค่าอ้างอิงจาก train เท่านั้น)
- ขยายการทดสอบ leakage ให้ครอบคลุม lag 5-8

- [ ] สร้าง lag 5-8 ของฝน, tmax, tmin (ยังไม่ได้ทำ — H3 ตัดสินไม่ได้อยู่แล้ว)
- [x] anomaly ต่อ fold โดยใช้ ref_mask จาก train (`folds.py:get_fold`)
- [x] ขยาย leakage test ครอบคลุม `wxa_*` ผ่าน `get_fold()` (12 tests passed)
- [ ] แคชตารางฟีเจอร์ผูกกับ config hash

**ผลลัพธ์:** ตารางฟีเจอร์ที่ผ่านการทดสอบ leakage

## ขั้น 2: H4 (ข้อหลัก)

- fit M0 และ M1 ต่อ fold หาผลต่าง MAE ของ D แบบจับคู่ต่อ fold
- เกณฑ์: ลด ≥ 5%, ดีกว่า ≥ 4/5 fold, CI ไม่คร่อมศูนย์ (block bootstrap ตามจังหวัด ภายในปี)
- แยกส่วนประกอบเพื่ออธิบายผล: อากาศดิบ / anomaly อย่างเดียว / ระยะสั้น (lag 0-4) / ระยะยาว (5-8, สะสม)
- sensitivity: ตัด 2020/2021, ต่างโมเดล (Huber/EN/HGB), รายเขต, รายปี
- รายงาน M1 ตามนิยามจริงก่อน แล้วค่อยรายงานรูปแบบที่เลือกแล้ว

- [x] รัน M0 vs M1 ตามนิยามเป๊ะบน 5 fold หลัก (HuberRegressor: 1/5 fold ผ่าน)
- [x] bootstrap CI ของผลต่าง (block-week, 100 reps; final ต้องการ 1,000)
- [ ] ablation แยกส่วนประกอบ (wx_raw only, anomaly only)
- [x] sensitivity (ElasticNetCV, HistGBR, XGBRegressor*, TabMMini*) *รันอยู่

**ผลลัพธ์:** ตารางผลต่อ fold, CI, คำตัดสิน H4 (ผ่าน / ไม่ผ่าน / ผ่านบางส่วน)

## ขั้น 3: H1 และ H2

- partial Spearman ระหว่าง anomaly อากาศ (lag 0-4) กับ D ภายในจังหวัด โดยคุมประวัติ แล้วรวมตามกติกาที่ล็อกไว้
- placebo: สลับอากาศข้ามปีภายในจังหวัดเดียวกัน (รักษาฤดูกาล ทำลายความสัมพันธ์จริง) ดูว่า \|ρ\| ตามบังเอิญสูงแค่ไหน เป็นไม้บรรทัดว่า 0.10 คือสัญญาณหรือเสียงรบกวน
- ฝนหลังควบคุมอุณหภูมิ (ตรวจว่าค่าลบของฝนมาจากอุณหภูมิหรือไม่)
- sensitivity: ทุกปี / ตัด 2021 / ตัด 2020-21

- [x] partial ρ ต่อ (ตัวแปร × lag × fold) → `mart.h_results` 105 แถว
- [x] placebo test (200 replicates) → `mart.h_placebo` 75 แถว
- [ ] ฝนคุมอุณหภูมิ (ยังไม่ได้ทำ)
- [ ] sensitivity ปี COVID (ยังไม่ได้ทำ)

**ผลลัพธ์:** ตาราง ρ ต่อ (ตัวแปร × lag × fold), ผ่าน/ไม่ผ่านของ H1 และ H2

## ขั้น 4: H3

- ขยาย lag เป็น 0-8 ใช้ผลจากขั้น 3
- เกณฑ์: มี lag ผ่านเกณฑ์อย่างน้อยหนึ่งค่า และ lag ที่ดีที่สุดไม่อยู่ที่ขอบ
- กราฟ ρ ต่อ lag พร้อมแถบข้าม fold

- [ ] โปรไฟล์ ρ ต่อ lag 0-8
- [ ] ตัดสิน H3 และกำหนด lag ที่เข้า M1 สุดท้าย

**ผลลัพธ์:** โปรไฟล์ lag ที่ชัดเจน

## ขั้น 5: ตรวจความสอดคล้องของทั้งสี่ข้อ

| ผลที่ออกมา | ตีความ |
|---|---|
| H1/H2 ผ่าน และ H4 ผ่าน | อากาศมีสัญญาณจริงและใช้ได้ |
| H1/H2 ไม่ผ่าน แต่ H4 ผ่าน | ผลมาจากกลไกอื่น (ระยะยาว, ไม่เชิงเส้น, หรือเป็นตัวแทนฤดูกาล) ต้องทดสอบด้วย Fourier ฤดูกาลใน M0 |
| H1/H2 ผ่าน แต่ H4 ไม่ผ่าน | สัญญาณมีแต่เล็กเกินกว่าจะเปลี่ยนความแม่นยำ |
